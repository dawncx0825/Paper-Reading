# ViT 单张 RTX 3090 复现报告与实验方案

> 创建日期：2026-09-21（新加坡时区）  
> 当前状态：**工程实现与短程验证已完成；完整学习率搜索和三 seed 正式实验正在服务器后台运行。**  
> 实测硬件：1 × RTX 3090，24GB 显存。计划值与实测值分别标明，正式准确率仍待长流程完成。

## 1. 结论与复现边界

**单张 3090 可以完成 ViT 的结构实现和下游全参数微调；不适合从零重做原论文的大规模预训练及整套实验。**

本项目第一版目标：使用原论文公开的 ImageNet-21k 预训练 ViT-B/16 权重，在 CIFAR-100 上微调，比较论文 Table 5 的 **91.67% Top-1 准确率**。这属于“复用预训练模型的下游实验复现”。达到接近的准确率有现实依据，但不提前承诺结果。

| 目标 | 单卡可行性 | 本版范围 |
| --- | --- | --- |
| 理解并实现 patch embedding、位置嵌入、Transformer encoder 和分类头 | 可行 | 实现阶段纳入 |
| ViT-B/16 在 CIFAR-100 上全参数微调 | 可行 | 主实验 |
| 冻结编码器，只训练分类头 | 可行，成本较低 | 辅助对照 |
| 随机初始化 ViT，与预训练初始化比较 | 可行，但可能需要不同的训练配方 | 可选扩展 |
| 从零在 ImageNet-1k 上训练 ViT-B/16 | 能运行，完整训练及调参成本高 | 暂不纳入 |
| ImageNet-21k / JFT-300M 预训练和多模型规模实验 | 单卡不现实 | 不纳入 |

原论文的关键论点之一是：随着预训练数据规模扩大，ViT 相对 CNN 的表现发生变化。本项目没有重做这些大规模预训练，不能据此宣称独立验证了完整的数据规模结论。小数据上的随机初始化对照也不能单独证明“ViT 天生不如 CNN”。

## 2. 论文依据与目标结果

论文：Alexey Dosovitskiy 等，*An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale*，ICLR 2021。

### 2.1 为什么不重做大规模预训练

| 原论文设置 | 论文报告值 | 对本项目的含义 |
| --- | --- | --- |
| ViT-B 参数量 | 约 86M，12 层，隐藏维度 768，12 个注意力头 | 可作为单卡微调对象 |
| ViT-L / ViT-H 参数量 | 约 307M / 632M | 第一版不增加模型规模 |
| 预训练 batch size | 4096 | 梯度累积能减少显存需求，但不会减少总计算量 |
| ViT-L/16，ImageNet-21k 预训练 | Table 2 约 230 TPUv3 核·天；正文称 8 核 TPUv3 约 30 天 | 完整重训成本远高于下游微调 |
| ViT-L/16、ViT-H/14，JFT 预训练 | Table 2 分别约 680、2500 TPUv3 核·天 | 另有 JFT 数据获取限制 |

以上来自论文 Table 1、Table 2、Table 3 和 §4。**TPUv3 核·天不能直接按固定比例换算成 3090 天数**，因此不沿用“单卡一定需要几年”之类未经基准测量的说法。

### 2.2 主实验的论文对照

| 项目 | 目标配置 / 论文结果 |
| --- | --- |
| 模型 | ViT-B/16 |
| 预训练来源 | ImageNet-21k |
| 下游数据集 | CIFAR-100，100 个细分类别 |
| 微调输入 | 384 × 384 |
| 微调方式 | 替换分类头，更新全部模型参数 |
| 论文 Top-1 | **91.67%** |
| 定位 | 第 15 页 Table 5，ImageNet-21k → CIFAR-100，ViT-B/16 列 |

同表的 CIFAR-10 结果为 98.95%，可作为后续扩展。Table 2 的 CIFAR-100 最佳结果 94.55% 对应更大的模型和不同预训练数据，不能作为本项目的直接验收目标。

[官方仓库](https://github.com/google-research/vision_transformer#available-vit-models)提供原论文 ImageNet-21k 权重，并报告 ViT-B/16 在 CIFAR-100 上约 92% 的后续复现结果。这里将它作为可行性证据；仓库中的其他硬件耗时不直接当作单张 3090 耗时。

## 3. 模型和权重方案

第一版建议采用 **PyTorch 实现 + 原论文官方预训练权重**，便于阅读模型、检查中间张量和在 3090 上调试；官方 JAX/Flax 实现用于核对结构、权重与训练细节。

| 部分 | 方案 |
| --- | --- |
| Patch embedding | 16 × 16 非重叠图块，映射到 768 维；可用等价的卷积实现 |
| Encoder | 12 层，12 个头，MLP 隐藏维度 3072，Pre-LayerNorm、GELU、残差连接 |
| 聚合 | 可学习的 class token，取最终归一化后的对应表示 |
| 位置嵌入 | 使用官方权重；从 224 改为 384 时，对 patch 对应部分进行二维插值 |
| 分类头 | 丢弃预训练头，新建 768 → 100 的线性层，权重和偏置零初始化 |
| 权重来源 | `gs://vit_models/imagenet21k/ViT-B_16.npz` |

[官方权重下载地址](https://storage.googleapis.com/vit_models/imagenet21k/ViT-B_16.npz)。下载后记录来源、大小和 SHA-256。原论文权重与后来发布的 AugReg、SAM 等权重分开处理；不能为了获得更高准确率而替换权重来源后仍称为相同实验。

如果借助 timm 加载或转换权重，必须核验模型标签及来源，不能只使用不明确来源的 `pretrained=True`。实现完成后，固定所用代码 commit 和依赖版本。

跨框架转换的必要检查：

1. 列出已加载、缺失和多余参数；仅允许预期的分类头差异。
2. 核对卷积核维度顺序、线性层转置、Q/K/V 排列、LayerNorm epsilon 和 GELU 形式。
3. 在相同输入、相同预处理下，对比转换前后的编码器输出，记录数值误差。
4. 224 输入对应 197 个 token；384 输入对应 577 个 token。class token 的位置嵌入不参与空间插值。
5. 记录位置插值算法及参数；论文仅规定二维插值，具体实现差异需要披露。

此处是实现要求，**当前没有训练代码，也没有完成权重转换验证**。

## 4. 数据准备与评测隔离

使用 [CIFAR-100 官方数据](https://www.cs.toronto.edu/~kriz/cifar.html)：50,000 张训练图片、10,000 张测试图片，原始分辨率为 32 × 32，每类 500 张训练图、100 张测试图。使用 fine labels，不使用 20 类 coarse labels。官方 Python 压缩包约 161 MB。

| 阶段 | 训练数据 | 验证 / 测试数据 | 用途 |
| --- | --- | --- | --- |
| 工程调试 | 训练集中的小子集 | 训练来源的调试样本 | 检查模型与梯度，不报告最终成绩 |
| 学习率选择 | 49,000 张 | 固定 1,000 张开发集 | 与论文留出 2% 训练数据的原则一致 |
| 正式复现 | 完整 50,000 张训练集 | 官方 10,000 张测试集 | 配置确定后训练和最终评测 |

开发集采用固定种子的分层抽样，每类 10 张；保存样本索引。它遵循论文的留出比例，但不声称与作者的样本 ID 完全相同。配置确定后，每次正式实验都从同一预训练权重重新开始，不能把开发阶段训练过的模型继续训练后视为独立正式运行。

测试集不参与学习率、随机种子、训练时长或 checkpoint 选择；主结果使用预先约定的最终更新步模型。评测覆盖全部 10,000 张测试图片，保留最后一个不足 batch 的批次，并按样本数汇总指标。

### 4.1 图像预处理

以[官方输入处理代码](https://github.com/google-research/vision_transformer/blob/main/vit_jax/input_pipeline.py)为核对依据：训练使用随机裁剪并缩放、随机水平翻转；验证与测试使用确定性的缩放；像素映射到 [-1, 1]。

PyTorch 版本需显式记录裁剪面积和宽高比范围、插值方式、抗锯齿设置及归一化，不默认使用其他 ImageNet 模型的均值方差。跨框架预处理不能只凭变换名称相同就视为完全一致。

CIFAR 的 32 × 32 图片放大到 384 × 384 是为了匹配迁移协议，不会创造额外图像信息。数据保持原始分辨率存储，读取时变换，不把全部图片预先展开成高分辨率浮点数组缓存。

### 5.2 梯度累积不能改变训练量

一次完整参数更新处理 512 张图，累计 10,000 次更新，共约 **512 万次样本呈现**；在 50,000 张训练集上相当于约 **102.4 个 epoch**。随机增强使重复呈现的输入可能不同。

当 micro-batch=16 时：

```text
每个小批次：前向 → loss / 32 → 反向累积
完成 32 个小批次：必要时取消梯度缩放 → 裁剪全局梯度 → optimizer.step
随后推进一次学习率调度，清空梯度
总计：10,000 次参数更新，320,000 个小批次
```

Warmup、调度器和 checkpoint 编号均按参数更新次数定义。仅因 micro-batch 变小而把学习率同步缩小，会改变预定实验；只要有效 batch 仍为 512，就先保持选定学习率。

### 5.3 显存不足时的处理顺序

1. 先将 micro-batch 从 16 降至 8，并相应增加累积次数。
2. 使用混合精度和经过验证的高效注意力实现；必要时启用激活检查点。
3. 单独调整评测 batch；评测无需与训练有效 batch 相同。
4. 224 分辨率用于调试或另列的低成本实验；改为 224 后不能直接宣称严格复现了 Table 5。

不要把模型参数文件大小当作训练显存需求。384 分辨率增加了 token 数和激活开销；注意力矩阵的规模按 token 数平方增长，但这不意味着总显存或总耗时也严格按同一倍数增长。

## 6. 实验顺序与对照设计

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| A：环境与数据 | 检查 CUDA、下载校验、固定数据划分、确认权重来源 | 能离线加载，来源和版本可追溯 |
| B：结构调试 | 224 分辨率小样本训练、权重转换核对、保存与重载 | loss 正常、梯度有效、预测可重复 |
| C：正式尺寸测速 | 384 分辨率、有效 batch=512；预热后测 100 次完整更新 | 无 OOM/NaN，获得耗时与显存记录 |
| D：选择学习率 | 在 49k/1k 开发划分比较四个论文候选学习率 | 只按开发集指标选配置 |
| E：主实验 | 完整 50k 数据、选定配置、三个 seed 各 10k 次更新 | 保留三个最终模型和独立测试指标 |
| F：汇总 | 汇总准确率、标准差、与论文差值、时间和显存 | 更新本报告的实测章节 |

四个学习率都跑完整 10,000 步是优先方案。若预算受限，可先用较短日程筛选，再对候选运行完整日程；这种筛选可能错过适合长日程的学习率，必须记录为相对完整搜索的偏离，不能隐去。

**推荐辅助对照：冻结编码器，只训练同结构的分类头。** 使用相同数据划分和评测规则，在开发集单独选择适合分类头训练的学习率，比较全参数适配是否有收益。这里的交叉熵分类头训练不同于论文 few-shot 部分的正则化最小二乘求解，不把二者混称为相同实验。

随机初始化 ViT 作为后续扩展。若只给它与微调组相同的 SGD 配方和步数，只能说明“在这一固定预算和配方下，预训练初始化的作用”；不能据此判断从零训练 ViT 的最佳水平。CNN 对照需要另行匹配训练预算、增强和调参机会，本版不预设结论。

CIFAR-100 数据体积较小，主要存储开销来自环境、预训练模型和训练快照。按每组保留最后模型及必要恢复点管理空间，不无上限保留每个中间 checkpoint。

### 7.2 用实测更新预算

暂以“单次正式运行数小时到一两天”作为宽泛排期参考；**该范围尚未在本项目的 3090 上验证，不构成完成时间承诺**。以阶段 C 测得的完整更新耗时替换估计。

计算方法：

```text
单次纯训练小时数 = 平均每次完整更新的秒数 × 10,000 / 3,600
总墙钟时间 = 纯训练时间 + 数据准备 + 验证 + 保存 + 最终评测
```

| 假设实测完整更新耗时 | 单次 10k 更新的纯训练时间 |
| --- | ---: |
| 2 秒 | 约 5.6 小时 |
| 5 秒 | 约 13.9 小时 |
| 10 秒 | 约 27.8 小时 |

上表是算术场景，不是性能测试。完整四学习率搜索加三个正式 seed，共相当于七次长运行；例如每次 5 秒/更新时，纯训练合计约 97.2 小时，尚不含辅助对照及其他开销。不能只预算一次训练就声称完成调参和重复验证。

训练和分类评测不需要付费模型 API。若使用租用 GPU，费用按实际 GPU 小时乘租价计算；若使用自有显卡，则记录训练时间和可获得的能耗信息。

## 8. 验收与结果报告规则

工程完成与数值接近是两项不同结果。

**工程验收：**

- 编码器预训练权重完整加载，分类头替换可追溯；关键张量和权重转换已检查。
- 正式配置能完成训练、保存、重载和全部测试样本评测。
- 单卡累积语义正确，没有把 micro-step 当成 optimizer step。
- 测试样本没有进入训练或配置选择；依赖、数据索引、种子及运行命令已保存。
- 数值异常、OOM、实际训练步数和任何配置偏离均有记录。

**结果验收：**

- 主指标：测试集 Top-1；每个 seed 单独报告，另报三次均值与样本标准差。
- 报告“本项目平均 Top-1 − 91.67%”，单位为百分点；原论文的单个表格值不当作零误差的真值。
- 可预先将“与 91.67% 的绝对差不超过 0.5 个百分点”设为本项目的接近目标，仅是项目约定，不是论文规定或统计等价检验。
- 未达到目标时如实报告，并依次检查权重、预处理、优化日程、参数转换及随机波动；结果偏低也可以形成完整、可信的复现报告。
- 更换权重、增强方法或模型后产生的更高分数，必须另列实验，不能覆盖原方案结果。
