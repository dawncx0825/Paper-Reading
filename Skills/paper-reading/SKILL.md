# 论文精读流程

帮助读者先建立论文的整体认识，再通过追问逐步理解细节。总结应当让读者看懂主要思路并能够提出具体问题；追问阶段优先围绕当前问题展开，避免引入过多未解释的概念。

以下是默认阅读方式，不预设读者身份、知识背景、历史对话或个人偏好。用户明确指定语言、深度、格式、讨论范围或归档方式时，以当前要求为准。没有额外要求时，使用中文说明并保留必要的英文术语，无需先填写个人配置。

## 第一步：论文总结

先取得并阅读论文原文。若只有标题或链接，使用当前环境可用的检索或文件工具获取对应版本；无法访问原文时说明缺失内容，不根据标题或记忆编造总结。用户只追问某个局部问题时，直接定位相关内容，不必重新生成整篇总结。

动手写总结前先读 [references/glossary.md](references/glossary.md)。这是一份可复用的初始术语表；同时参考当前项目已有的术语约定。保持同一项目内译法一致，遇到学科差异或论文的特殊定义时，以原文语境为准并说明差异。

默认按以下顺序组织，先建立 §0，再写正文：

```text
§0 术语对照表      本篇实际使用的英文名词 → 中文译法 / 或标注“保留英文”
§1 这篇论文要解决什么问题
§2 方法             沿论文的方法章节顺序解释，补足必要依赖
§3 实验与主要结果    对照原文核实数字、条件和比较对象
§4 局限与待核实之处  区分作者承认的局限、可核实的问题和读者的疑问
```

§0 只列本篇确实用到的术语。新词先在本篇确定译法；需要跨论文复用时，按术语表中的维护规则记录。

总结完成后停下，等待读者选择下一步，不自行预告或展开下一个讲解主题。确有尚未展开的关键概念时，可在末尾简列一至两个供追问；若依赖更多，应先在正文补足必要解释。用户要求一次完成深入讲解时，按其要求继续。

## 第二步：追问阶段

- **默认一轮聚焦一个核心概念**，回答当前问题后停下；用户同时提出多个问题或要求综合说明时，按要求回答。
- **依赖前置**。符号和必要名词应先定义。遇到前置知识缺口，先简要补足；需要较长解释时，说明当前概念依赖什么，再分步展开。
- **比较应有基础**。对照两个概念前，先确保各自的含义已交代清楚。
- **纠错聚焦错误本身**。指出错误、给出正确表述及必要依据，不夹带无关的新主题。自行发现错误时也应简洁更正。
- **区分已解释与已理解**。不要因为输出过解释就假设读者已经掌握，也不要把沉默当作确认或不理解的证据；必要时根据后续反馈调整深度。

## 术语规则

- **同一英文词族尽量保留可辨认的中文词根**。mis-、un-、non- 等前缀应结合语境表达错误、缺失或否定，不机械地统一成同一种译法。
- **honesty（诚实）与 truthfulness（真实性）应区分**。涉及意图、表达和事实正确性时，核对论文自身的定义，不混用相关概念。
- **专业名词可优先保留英文**，首次出现时给出中文含义；读者要求中文译名时，采用稳定译法并保留首次中英对照。
- **不自造会混淆论文对象的统称**。例如，reward model、模型输出的 reward 和加入 KL 惩罚的优化目标需要分别说明，不能用一个含糊的名称替代。

## 内容边界与核验

- 以论文内容为主。帮助理解所需的背景知识应明确标为背景；用户要求扩展、比较或评论时，区分论文结论、外部资料与分析判断。
- **准确说明概念的作用环节与因果关系**。例如讨论 reward hacking 时，应依据当前论文区分奖励模型的局限与策略优化对奖励信号的利用，不能把某篇论文的讨论写成适用于所有论文的阶段归属。
- **数字、公式、图表和章节引用必须对照原文核实**。同时核对论文版本、实验条件、指标定义与比较对象。无法核实的内容明确标注，不凭印象报数。
- **有依据的问题应指出，尚未证实的疑点应保留不确定性**。例如排版错误、评估设置不清或论证缺口；不要为了填满“局限”一节而制造批评。

## 排版

默认使用连贯、长度适中的段落。小标题服务于阅读结构，分点用于真正并列的内容，避免把完整论述拆碎。术语、实验数据、超参数和概念比较适合使用表格；叙述性解释优先用正文。用户指定格式时遵循其要求。

## 论文里的图

讲解架构图、流程图或结果图时，优先展示论文原图，保留图号、图例和必要上下文。只展示当前相关的图，并标注来源页码或图号。

使用当前环境已有的 PDF 阅读、截图或裁剪工具。需要本地裁剪且已安装 PyMuPDF 时，可参考以下示例；输入路径、页码和裁剪坐标都必须按实际论文调整：

```python
from pathlib import Path
import fitz

paper_path = Path("paper.pdf")  # 替换为实际论文路径
output_dir = Path("outputs")   # 替换为项目指定的输出目录
output_dir.mkdir(parents=True, exist_ok=True)
with fitz.open(paper_path) as doc:
    page = doc[3]  # 示例：第 4 页，索引从 0 开始
    page.get_pixmap(dpi=150).save(str(output_dir / "page-4.png"))
    # 先检查整页图，再根据实际图像位置设置 PDF 坐标（points）
    rect = fitz.Rect(60, 90, 540, 360)
    page.get_pixmap(dpi=200, clip=rect).save(str(output_dir / "figure.png"))
```

不要假定某个固定目录、侧栏或文件展示工具存在。使用当前平台支持的图片、附件或文件链接展示结果；无法展示时给出图号、页码和解释。缺少依赖时优先使用现有工具，确需安装则使用项目虚拟环境或平台提供的依赖环境。

## 笔记归档

遵循用户指定的项目目录和命名方式。没有指定但需要保存文件时，可使用当前项目中的 `Papers/<论文简称>/`，按需保存原文、总结、问答和图像。不要求读者拥有特定 GitHub 仓库，也不因启用本技能而自动上传或提交内容。

默认保留已定稿笔记的历史：后续补充可写入单独文件；用户要求更新旧文档或发现实质错误时，应修订相应内容，并在有需要时简记更正原因。无需把每一轮对话都自动归档。

## 常见问题自检

- 是否对同一术语使用了无法对应的译名，或把不同对象合并成一个名称？
- 是否把特定论文的结论推广成了通用定律？
- 是否有未经原文核实的数字、公式、章节或图号？
- 是否在纠错或回答单个问题时引入了过多无关概念？
- 是否让零碎分点妨碍了完整论述，或自行替读者决定了下一步阅读主题？
